# HW14 — Transactions implementation plan

**Goal:** Pass the supplied HW14 acceptance criteria on a fresh database.
**Architecture:** TypeORM transaction managers execute parameterized SQL. Atomic
stock and balance updates, order/item/job inserts commit together. Workers hold
SKIP LOCKED locks through processing and commit the receipt with the counter.
Retry recreates the entire transaction, including reads.
**Spec:** User-supplied `homework-14-transactions.md` (2026-09-27).

## Constraints and decisions

- Keep root package.json and existing hw-14 checkout; no new env files.
- Add balance_cents bigint (represented as string) and queue through a reversible
  migration, with matching entities; synchronize remains false.
- Keep historical HW13 seed counts. Give seeded buyers ample balances on insert.
- Demo fixtures use generated IDs and clean up only their own rows, including on
  failure. They can run independently or repeatedly without changing HW13 data.
- Exactly-once applies to committed database results, not external email delivery.
- Native execution follows the user's instruction to start when requirements are
  clear; no extra design approval or automatic commit/push is needed.
