## Фактичні демо

Останній повторний прогін на окремій БД:

```text
Спроб: 50; успішних: 10; фінальний stock: 0; рядків із відʼємним stock: 0
Розподіл задач: { 'worker-1': 4, 'worker-2': 4, 'worker-3': 4 }
оброблено двічі: 0; оброблено: 12; час: 444.1 ms; послідовно: ≥ 1200 ms
Retry 1: PostgreSQL 40001, backoff 32 ms
Повторів: 1; фінальний баланс: 102; очікується: 100 + 1 + 1 = 102
```

Попередні прогони workers: 451.3 ms на основній навчальній БД і 435.0 ms
на чистому стенді; інші інваріанти однакові. Час і jitter залежать від запуску.

Інтеграційні тести перевіряють insufficient stock/balance, некоректну quantity,
відкат при помилці INSERT jobs, конкуренцію двох товарів за один баланс,
точність балансу й добутку ціна × кількість понад Number.MAX_SAFE_INTEGER,
відкат обробки задачі та повторне підбирання після зняття блокування,
обмеження спроб і відсутність retry для сторонніх кодів.

Незалежне статичне рев’ю не знайшло блокувальних проблем. Вказаний ним
пропуск тестів конкуренції балансу й великих сум покрито фінальним тестом.

## Межі перевірки

Infisical не використовувався для runtime-прогону: перевірено передбачений
завданням шлях грейдера SKIP_VAULT=1 та наявність незміненої обгортки в scripts.
Нових залежностей і env-файлів немає. npm ci показує наявні попередження
про deprecated залежності; Vitest — рекомендацію щодо vite-tsconfig-paths.
Команди завершилися успішно.

Завдання виконано в робочій гілці; commit, push та PR не створювалися.
Для здачі в LMS потрібне посилання на PR із hw-14, як зазначено в умовах.
