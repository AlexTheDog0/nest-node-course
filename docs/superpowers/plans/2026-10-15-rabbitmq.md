# RabbitMQ implementation plan

Goal: meet HW19's nine acceptance criteria in the existing root service on hw-19.
Architecture: checkout publishes an explicit stable order.placed contract after COMMIT; bootstrap owns topology; consumer records a durable unique order receipt before manual ACK. No transactional outbox yet.

1. Add contract validation tests, stable event IDs, confirm publisher with mandatory returns, and consumer-owned quorum topology (DLX/DLQ).
2. Add receipt migration and consumer. A receipt is the effect itself, keyed by eventId and orderId, eliminating a separate marker/effect transaction gap. Transient storage errors stop the consumer without acknowledging; invalid contracts are rejected.
3. Inject publication into checkout after COMMIT. Existing callers without a broker remain usable; broker-configured checkout publishes automatically.
4. Add isolated, self-checking publish/DLQ/duplicate demos using real checkout and PostgreSQL. Duplicate is caused by nack after the first durable effect. Assert counters and queue depths with deadlines.
5. Add RabbitMQ healthcheck, secret provisioning, wrapper scripts, README setup and measured outputs.
6. Verify tsc, unit tests, real demos, repeated runs and existing checkout tests. Document DB/broker atomicity gap and prefetch budget.

Review focus: rollback must not publish; unroutable messages must fail publication; persistent uniqueness must survive consumer replacement; poison payloads must report actual x-death; demo cleanup must only remove owned resources.
