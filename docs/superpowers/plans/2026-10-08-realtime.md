# Realtime Implementation Plan

> Implement inline using superpowers:executing-plans; verify with test-driven-development and verification-before-completion.

**Goal:** Fulfil HW18's WS room isolation, SSE replay, measurable demo and README criteria.
**Architecture:** OrdersService owns transactional status changes and publishes after commit. A singleton OrderEventsService uses RxJS Subject and a bounded process-local history; a gateway and SSE controller consume the same events. HMAC tokens identify owners; local setup issues expiring demo credentials offline.
**Tech Stack:** NestJS 12, PostgreSQL, RxJS, Socket.IO, Node crypto; tsc → node dist.
**Spec:** User-supplied hw-18-realtime-websockets-sse-rxjs.md and approved minimal signed tokens.

## Constraints
- Branch hw-18; src/**/*.gateway.ts, src/**/order-events.service.ts, src/**/orders.controller.ts, scripts/realtime-demo.mjs.
- Join orders:<id> only after ownership validation; ack before HTTP change.
- SSE includes id, event, JSON data; Last-Event-ID replays only greater IDs for requested order.
- Publish from business service after commit, never directly from controller.
- Both demo modes share code and measure delivery; README has exact trade-offs heading and four criteria.

## Review focus
- Forged/expired tokens and foreign orders must not grant access.
- Concurrent/failed writes must not publish uncommitted events.
- Replay/live boundary must neither lose nor duplicate events.
- Slow/disconnected clients must release subscriptions and timers.
- Missing setup, failed joins and missing A delivery must fail the demo rather than hang.
